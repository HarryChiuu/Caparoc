fix(forward-open): 修正 Large Forward Open 封包結構

根據專家分析，完全重構 Forward Open 請求：

1. 關鍵錯誤修正 ✅
   
   之前的錯誤：
   ❌ 將 Config/Output/Input 路徑串接: "20 04 24 66 2C 64 2C 65"
   ❌ 路徑指向錯誤的物件
   ❌ Header 與 Config 資料重疊
   
   正確結構：
   ✅ Connection Path → Connection Manager (Class 0x06, Instance 0x01)
   ✅ Configuration Path → Assembly 0x66 (Config)
   ✅ Consuming Path → Assembly 0x64 (Output, O->T)
   ✅ Producing Path → Assembly 0x65 (Input, T->O)
   ✅ Config Data 獨立附加 (244 bytes)

2. Large Forward Open 完整結構 ✅
   
   Standard Header (36 bytes):
   - Priority/Tick, Timeout, Connection IDs
   - Vendor ID, Serial Numbers, Multiplier
   - O->T/T->O RPI, Connection Parameters
   - Transport Type
   
   Connection Path (4 bytes):
   - Size: 1 word
   - Path: Class 0x06, Instance 0x01 (Connection Manager)
   
   Configuration Application Path (5 bytes):
   - Size: 2 words
   - Path: Class 0x04, Instance 0x66 (Config Assembly)
   
   Consuming Connection Path (5 bytes):
   - Size: 2 words  
   - Path: Class 0x04, Instance 0x64 (Output Assembly)
   
   Producing Connection Path (5 bytes):
   - Size: 2 words
   - Path: Class 0x04, Instance 0x65 (Input Assembly)
   
   Configuration Data (246 bytes):
   - Size: 2 bytes (244)
   - Data: 244 bytes

3. 封包長度計算 ✅
   - Standard Header: 36 bytes
   - Connection Path: 4 bytes
   - Config Path: 5 bytes
   - Consuming Path: 5 bytes
   - Producing Path: 5 bytes
   - Config Data: 246 bytes (2 + 244)
   - 總計: 301 bytes (不是 288!)

4. 除錯輸出增強 ✅
   - 顯示每個欄位的偏移量和內容
   - 結構化顯示各個 Path
   - Config Data 位置正確標示
   - 避免 Header/Data 重疊問題

5. 關鍵修正說明
   
   問題根源：
   - 手動串接路徑是錯誤的
   - 必須使用 Large Forward Open 的多路徑結構
   - 每個路徑必須獨立定義，有自己的 Size 欄位
   
   解決方案：
   - 按照 CIP Vol1 3-5.5.1 規範建構
   - Connection Path → Connection Manager
   - 三個獨立的 Application Path (Config/Consuming/Producing)
   - Config Data 正確附加在最後

此版本解決封包結構錯誤，避免設備丟棄請求
