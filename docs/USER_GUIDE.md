# CAPAROC 控制器 - 使用手冊

> **程式版本**: v4.2 (Phase 4.2 Web UI)  
> **更新日期**: 2026-05-25  
> **Web UI**: `python web/app.py`（主要操作方式）  
> **CLI**: `python src/caparoc_controller.py`（命令列操作）  
> **装置逾輯**: `src/caparoc_backend.py` ← 繼承 ← `CaparocController`（CLI）/ `web/app.py`（Web UI）

---

## 📋 概述

CAPAROC 控制器是基於 EtherNet/IP 協議的斷路器模組管理程式，提供 Web UI 圖形介面與 CLI 互動介面两種操作方式。

### ✨ 主要功能

- ✅ **Web UI 控制介面** — `python web/app.py` 自動開啟瀏覽器，6 個功能頁面
- ✅ **通道開閘控制** — Web UI `on`/`off` 按鈕 或 CLI `on`/`off` 指令
- ✅ **額定電流設定** — Web UI 通道設定頁 或 CLI `init` 指令設定 1–20A
- ✅ **即時图表監控** — 每模組独立折線圖，30 分鐘歷史、拖曳縮放
- ✅ **系統日誌頁** — 等級笻選、分頁、請求/暂停更新
- ✅ **設備識別資訊** — 廠商、型號、序號、MAC、網路設定
- ✅ **多模組支援** — 自動偵測 1–16 個模組（最多 64 通道）
- ✅ **CLI 即時監控** — 胍景執行緒定期更新，支援靜默/顯示模式
- ✅ **IP 配置** — 啟動時可變更設備 IP，持久化儐定預設

### 🎯 適用場景

- 工業自動化控制
- 多通道負載管理
- 電流監控與保護
- 遠端設備控制

## 🚀 快速開始

### 1. 環境準備

```bash
# 啟動 Conda 環境（本機開發環境名為 sv；用 environment.yml 全新建立的話是 caparoc_breaker）
conda activate sv

# 確認已安裝依賴
pip install pycomm3>=1.2.14
```

### 2. 啟動程式

#### 2.1 Web UI 啟動（建議方式）

```bash
# 進入專案目錄
cd c:\Users\harry\Project\Caparoc5

# 啟動 Web 服務（預設自動開啟瀏覽器）
python web/app.py

# 或手動開啟瀏覽器
http://localhost:8000
```

**啟動後會自動連線設備**，聯線成功後即可操作各頁面功能。

#### 2.2 CLI 啟動

```bash
# 進入專案目錄
cd c:\Users\harry\Project\Caparoc5

# 啟動控制器 (使用預設 IP: config/device_config.json)
python src/caparoc_controller.py

# 或指定 IP 位址
python src/caparoc_controller.py --ip 192.168.1.100
```

## 🌐 Web UI 操作指南

### 3.1 儀表板（Dashboard）

首頁預設頁面。顯示所有通道的即時狀態。

| 元素 | 說明 |
|---|---|
| 通道卡片 | 每通道独立卡片：開閘狀態、實際電流、額定電流、使用率 |
| 開/關按鈕 | 即時控制該通道 ON/OFF |
| 先前指示燈 | 🟢 經常 / ⚫ 關閉 / ⚠️ 80%警告 / 🔴 過載短路 |
| 全域狀態列 | 系統電壓、總電流、模組數量 |

---

### 3.2 通道設定頁（Channel Settings）

設定各通道的額定電流，對應 CLI `init` 指令。

| 操作 | 說明 |
|---|---|
| 封列輸入欄 | 輸入整數電流傀 (1–20 A)，點「設定」按鈕应用 |
| 全部套用 | 批次將所有通道設為相同額定電流 |
| 即時填入 | 表格資料自動從 WebSocket 狀態填入，無需手動更新 |

---

### 3.3 圖表監控頁（Charts）

視覺化電流/電壓歷史趨勢。

| 元素 | 說明 |
|---|---|
| 全域曲線 | 雙 Y 軸：電壓（V，左）+ 總電流（A，右） |
| 模組曲線 | 每模組各一張圖，各通道一條色線 |
| 视窗大小 | 30ㅧ0ㅢㅢ0 秒切換，即時模式滾動更新 |
| 縮放查看 | 滑鼠拖曳/滾輪縮放（chartjs-plugin-zoom），『► 即時』按鈕跳回即時 |
| 歷史預載 | 連線成功後自動載入後端最近 30 分鐘資料 |
| 暂停/恢復 | 暂停時停止積累新資料，不影響設備狀態顯示 |

---

### 3.4 系統日誌頁（Logs）

在網頁查看後端運作日誌，取代需要看終端機的問題。

| 元素 | 說明 |
|---|---|
| 等級笻選 | 全部 / WARNING+ / ERROR |
| 顏色編碼 | INFO 藍、SYSTEM 紫、WARNING 橙、ERROR 紅、DEBUG 灰 |
| 每頁溝 | 10 / 20 条切換 |
| 自動更新 | 每 2 秒輪詢，可暂停；恢復時跳回第 0 頁（最新） |
| 🔄 手動重新整理 | 暂停自動更新時可手動觸發 |
| 清空 | 清除記憶體 buffer，不影響磁碟 log 檔 |

---

### 3.5 系統狀態頁（System Status）

透過 CIP 協議一次性讀取設備身份資訊與全域設定。

**設備識別面板**（CIP Identity Object 0x01:1）：廠商 ID、設備類型、產品代碼、修訂版本、序號、產品名稱

**全域設定面板**（Class 0x0F, Inst 1–4）：param_lock、ui_lock、啟動延遲、操作模式

- 未連線時顯示上次連線的快取資料（標記「（上次連線資訊）」）
- 含 ↻ 手動重新整理按鈕

---

### 3.6 連線設定頁（Connection）

管理連線 IP 與查看設備網路設定。

**連線表單**：輸入 IP 位址 → 點「連線」按鈕；連線後可點「斷線」

**設備網路資訊面板**（連線後自動查詢）：

| 欄位 | CIP 來源 |
|---|---|
| IP 位址 | 0xF5, Inst 1, Attr 3 |
| 子網路遠罩 | 0xF5, Inst 1, Attr 3 |
| 預設閘道 | 0xF5, Inst 1, Attr 3 |
| MAC 位址 | Ethernet Link 0xF6, Attr 3 |
| 主機名稱 | 0xF5, Inst 1, Attr 5 |

### 1. 額定電流設定

#### `init <通道編號> <電流值>`

設定指定通道的額定電流 (1-20A)。

**語法**:
```
init <ch> <amps>
```

**參數**:
- `<ch>`: 通道編號 (1 到總通道數)
- `<amps>`: 電流值 (1-20A)

**範例**:
```
🎮 > init 1 4
正在設定 CH1 額定電流為 4A...
✅ CH1 額定電流設定成功: 4A

🎮 > init 5 6
正在設定 M2.CH1 (#5) 額定電流為 6A...
✅ M2.CH1 (#5) 額定電流設定成功: 6A
```

**注意事項**:
- 使用 Config Assembly Read-Modify-Write 安全更新
- 設定後會自動驗證
- 支援多模組環境

---

#### `verify <通道編號>`

驗證指定通道的額定電流設定值。

**語法**:
```

### 4. 即時監控

#### `monitor start [interval] [mode]`

啟動即時監控模式。

**語法**:
```
monitor start [interval] [mode]
```

**參數**:
- `[interval]`: 更新頻率 (秒)，預設 2 秒，範圍 0.5-60
- `[mode]`: 監控模式，預設 `silent`
  * `silent` - 靜默模式，僅在狀態變化時顯示警報
  * `display` - 顯示模式，定期顯示完整狀態

**範例**:

**靜默模式** (僅警報):
```
🎮 > monitor start 2 silent
🔄 監控執行緒啟動 (更新頻率: 2.0s, 靜默模式 (僅警報))
✅ 監控已啟動

# 只在有變化時顯示
⚠️  [14:32:15] 通道狀態變化:
   - CH1: OFF → ON (0.45A)
```

**顯示模式** (定期輸出):
```
🎮 > monitor start 2 display
🔄 監控執行緒啟動 (更新頻率: 2.0s, 顯示模式)
✅ 監控已啟動

[14:30:25] V:24.15V | I:1.20A | CH1:🟢0.45A CH2:⚫0.00A CH3:🟢0.75A CH4:⚫0.00A
[14:30:27] V:24.16V | I:1.21A | CH1:🟢0.46A CH2:⚫0.00A CH3:🟢0.75A CH4:⚫0.00A
[14:30:29] V:24.15V | I:1.20A | CH1:🟢0.45A CH2:⚫0.00A CH3:🟢0.75A CH4:⚫0.00A
```

**快速啟動** (使用預設值):
```
🎮 > monitor start
✅ 監控已啟動 (2秒更新, 靜默模式)

### 5. 連線設定

#### `setting`

開啟連線 IP 設定選單，提供四個子選項管理程式連線 IP 與設備硬體 IP。

**語法**:
```
setting
```

**互動選單**:
```
🎮 > setting

============================================================
⚙️  連線設定
============================================================
  目前連線 IP: 192.168.2.111
  預設 IP:     192.168.2.111  (config/device_config.json)
------------------------------------------------------------
  [1] 變更並連線       - 輸入新 IP，立即重連
  [2] 恢復預設值       - 使用 config.json 的 IP 重連
  [3] 存為預設值       - 將目前連線中的 IP 存入 config.json
  [4] 硬體 IP 修改     - 透過 CIP 修改設備 IP（成功後自動存檔並重連）
  [0] 返回主選單
============================================================

請選擇 [0/1/2/3/4]:
```

**子選項說明**:

| 選項 | 功能 | 是否重連 | 是否更新 config.json |
|------|------|----------|----------------------|
| `[1]` 變更並連線 | 輸入新 IP，立即重連 | ✅ 自動 | ❌（需手動 [3] 存檔） |
| `[2]` 恢復預設值 | 切回 config.json 記錄的 IP 並重連 | ✅ 自動 | ❌ |
| `[3]` 存為預設值 | 將目前連線 IP 寫入 config.json | ❌ | ✅ 立即寫入 |
| `[4]` 硬體 IP 修改 | CIP Class 0xF5 寫入設備 IP | ✅ 自動 | ✅ 自動 |

**典型使用流程**:
```
# 情境 1：切換到新設備
🎮 > setting
請選擇 [0/1/2/3/4]: 1
新 IP 位址 (或輸入 cancel 取消): 192.168.2.200
  ✅ 連線 IP 已設為 192.168.2.200
  🔄 使用新 IP 重新連線...
# → 連線成功後，若確認這個 IP 正確，再執行 setting [3] 存檔

# 情境 2：連線失敗時救回上次成功的 IP
🎮 > setting
請選擇 [0/1/2/3/4]: 2
  ✅ 已恢復為預設 IP 192.168.2.111
  🔄 重新連線...

# 情境 3：確認目前 IP 為長期預設
🎮 > setting
請選擇 [0/1/2/3/4]: 3
  ✅ 已將 192.168.2.200 設為預設 IP

# 情境 4：實體修改設備 IP（需 Npcap 環境）
🎮 > setting
請選擇 [0/1/2/3/4]: 4
  → 進入 CIP Class 0xF5 硬體 IP 設定子選單
  → 寫入成功後自動更新 config.json 並重連
```

**注意事項**:
- `[1]` 變更後不自動存檔，請使用 `[3]` 手動確認後存入
- `[2]` 的「預設值」來自 `config/device_config.json`，由 `[3]` 或 `[4]` 寫入
- `[4]` 需要設備支援 CIP Class 0xF5 寫入（部分環境需 Npcap）

## 🐛 故障排除

### 問題 1: 無法連接到設備

**錯誤訊息**:
```
❌ 裝置連線失敗!
   IP 位址: 192.168.2.111
   錯誤: 無法建立連線
```

**解決方案**:
1. 確認設備已開機
2. 檢查網路線連接
3. 確認 IP 位址正確
4. 使用 `ping` 測試連通性：
   ```powershell
   ping 192.168.2.111
   ```
5. 檢查防火牆設定 (Port 44818)
6. 確認電腦與設備在同一網段

---

### 問題 2: 通道控制無反應

**症狀**: 執行 `on 1` 後電流仍為 0

**可能原因**:
1. 額定電流未設定
2. 設備處於保護模式
3. 負載未連接

**解決方案**:
```
# 1. 檢查額定電流
🎮 > verify 1

# 2. 如果未設定，先設定額定電流
🎮 > init 1 4

# 3. 再次開啟通道
🎮 > on 1

# 4. 檢查狀態
🎮 > s
```

---

### 問題 3: 監控模式無輸出

**症狀**: `monitor start` 後沒有任何顯示

**原因**: 使用了靜默模式 (預設)

**解決方案**:
```
# 停止監控
🎮 > monitor stop

# 使用顯示模式重新啟動
🎮 > monitor start 2 display
```

---

### 問題 4: 連線中斷

**症狀**: 操作中出現連線錯誤

**解決方案**:
```
# 使用 reconnect 命令重新連線
🎮 > reconnect
```

- **通訊協議**: EtherNet/IP (CIP)
- **預設 Port**: 44818
- **支援模組**: 1-16 個

## 📋 日誌系統

### 日誌檔案位置

所有操作與事件均記錄於：

```
logs/caparoc_YYYY-MM-DD.log
```

每天自動建立一個新檔案（UTC+8 日期）。

### 日誌格式

```
2026-05-18 14:30:00 [LEVEL] [MODULE] 訊息內容
```

### 日誌等級說明

| 等級 | 用途 | 顏色（Web UI） |
|------|------|---------------|
| `DEBUG` | 偵錯用詳細資訊 | 灰色 |
| `INFO` | 一般操作紀錄（連線、斷線、設定完成）| 藍色 |
| `SYSTEM` | 系統關鍵事件（服務啟動／關閉）| 紫色 |
| `WARNING` | 異常但可繼續（設備讀取失敗、心跳超時）| 橙色 |
| `ERROR` | 操作失敗（指令執行錯誤、設備回應異常）| 紅色 |
| `CRITICAL` | 嚴重錯誤 | 深紅色 |

### log_module 標籤對照表

每筆 log 的 `[MODULE]` 欄位標示操作來源，方便篩選與診斷：

| MODULE | 意義 | 典型訊息 |
|--------|------|----------|
| `CLI` | CLI 程式操作（Controller 啟動、指令執行）| `CAPAROC PM EIP Controller 啟動` |
| `WEB` | Web 服務事件（伺服器啟動、API 呼叫）| `Web 服務啟動...` |
| `CONN` | 網路連線狀態（CIP 連線、斷線、心跳、設備失聯）| `設備失聯 (192.168.1.10)` |
| `CTRL` | 通道控制指令（on/off）| `通道 CH1 設定為 ON` |
| `INIT` | 額定電流設定 | `CH1 額定電流設定為 4A` |
| `SETTING` | 設定變更（IP 等）| `設備 IP 更新為 192.168.1.10` |
| `SYS` | 其他系統訊息 | - |

### 設備失聯時的 log 行為

當設備突然斷電或網路中斷時，程式會自動寫入以下 log（只記一次，不會每秒重複）：

```
2026-05-18 14:35:00 [WARNING] [CONN] 設備失聯 (192.168.1.10)，讀取狀態失敗: ConnectionError: ...
```

設備恢復回應後，自動補寫：

```
2026-05-18 14:36:20 [INFO] [CONN] 設備恢復回應 (192.168.1.10)
```

> 心跳機制（每 300 秒觸發）失敗時也會寫入 `[CONN] WARNING: 心跳失敗` 訊息。

### Web UI 日誌頁面

在 Web UI 的「系統日誌」分頁可即時查看 log：

- **等級篩選**：ALL / WARN+ / ERROR+
- **分頁大小**：10 / 20 筆
- **自動更新**：每 2 秒拉取最新，可暫停
- **清除**：清空目前記憶體緩衝（不刪除磁碟 .log 檔）
