## 功能概述

### 功能描述
標稱電流設定功能允許使用者透過 CLI 命令動態修改 CAPAROC 設備各通道的額定電流值（1-20A）。

### 使用情境
- 更換不同規格的負載設備
- 調整過電流保護閾值
- 系統初始化或重新配置

### 技術特點
- ✅ 支援運行時修改（不需重啟設備）
- ✅ 使用 EtherNet/IP CIP 協議
- ✅ 自動解鎖保護參數
- ✅ 即時驗證設定結果
- ⚠️ 需要正確的權限和參數解鎖順序

## 階段 1: CLI 命令處理

### 1.1 命令格式

**標準格式**:
```
init <通道編號> <電流值>
```

**範例**:
```bash
init 1 5      # 設定 CH1 為 5A
init 2 10     # 設定 CH2 為 10A
init 8 3      # 設定 CH8 (M2.CH4) 為 3A
```

### 1.2 參數驗證流程

#### 步驟 1: 命令格式檢查
```python
parts = cmd.split()
if len(parts) != 3:
    print("❌ 用法: init <通道編號> <電流值>")
    return
```

**可能錯誤**:
- 參數過少: `init 1` → 缺少電流值
- 參數過多: `init 1 5 10` → 多餘參數

---

#### 步驟 2: 通道編號驗證
```python
channel = int(parts[1])
total_channels = self.num_modules * 4

if channel < 1 or channel > total_channels:
    print(f"❌ 通道編號必須在 1 到 {total_channels} 之間")
    return
```

**驗證規則**:
- 最小值: 1
- 最大值: `模組數量 × 4`
  - 2 模組系統: 1-8
  - 3 模組系統: 1-12

**可能錯誤**:
- 通道編號 0 → 無效（最小為 1）
- 通道編號 > 總數 → 超出範圍
- 非數字輸入 → ValueError

---

#### 步驟 3: 電流值驗證
```python
current_amps = int(parts[2])

if current_amps < 1 or current_amps > 20:
    print("❌ 標稱電流必須在 1A 到 20A 之間")
    return
```

**驗證規則**:
- 最小值: 1A
- 最大值: 20A
- 資料型態: 整數

**可能錯誤**:
- 電流值 0 → 無效（最小為 1）
- 電流值 > 20 → 超出規格
- 小數值 (如 5.5) → TypeError

---

#### 步驟 4: 模組/通道計算
```python
module = (channel - 1) // 4 + 1
ch = (channel - 1) % 4 + 1

print(f"📝 設定 Module {module}, Channel {ch} 標稱電流為 {current_amps}A")
```

**計算邏輯**:
| 全域通道 | 模組 | 通道 | 計算過程 |
|---------|------|------|---------|
| CH1 | M1 | CH1 | (1-1)//4+1=1, (1-1)%4+1=1 |
| CH2 | M1 | CH2 | (2-1)//4+1=1, (2-1)%4+1=2 |
| CH4 | M1 | CH4 | (4-1)//4+1=1, (4-1)%4+1=4 |
| CH5 | M2 | CH1 | (5-1)//4+1=2, (5-1)%4+1=1 |
| CH8 | M2 | CH4 | (8-1)//4+1=2, (8-1)%4+1=4 |

---

### 1.3 錯誤訊息對照表

| 錯誤類型 | 錯誤訊息 | 原因 | 解決方法 |
|---------|---------|------|---------|
| 格式錯誤 | `用法: init <通道編號> <電流值>` | 參數數量不正確 | 檢查命令格式，確保有 2 個參數 |
| 通道超限 | `通道編號必須在 1 到 X 之間` | 通道編號超出範圍 | 檢查系統模組數量，調整通道編號 |
| 電流超限 | `標稱電流必須在 1A 到 20A 之間` | 電流值超出規格 | 調整電流值至 1-20A |
| 型態錯誤 | `invalid literal for int()` | 輸入非數字 | 確保通道和電流都是整數 |
| 連線錯誤 | `❌ 未連接到設備，請先使用 'connect' 命令` | 未建立連線 | 先執行 `connect <IP>` |

### 2.2 Parameter Instance 計算

#### Module 1 參數對應
| 通道 | 標稱電流 Param | Lock Param | Offset | 說明 |
|------|---------------|------------|--------|------|
| CH1 | Param 6 | Param 7 | 6 bytes | 第一通道 |
| CH2 | Param 9 | Param 10 | 9 bytes | 第二通道 |
| CH3 | Param 12 | Param 13 | 12 bytes | 第三通道 |
| CH4 | Param 15 | Param 16 | 15 bytes | 第四通道 |

#### Module 2 參數對應
| 通道 | 標稱電流 Param | Lock Param | Offset | 說明 |
|------|---------------|------------|--------|------|
| CH1 | Param 18 | Param 19 | 18 bytes | 第一通道 |
| CH2 | Param 21 | Param 22 | 21 bytes | 第二通道 |
| CH3 | Param 24 | Param 25 | 24 bytes | 第三通道 |
| CH4 | Param 27 | Param 28 | 27 bytes | 第四通道 |

#### 計算公式
```python
# 標稱電流參數編號
base_offset = (module - 1) * 12  # 每個模組偏移 12
param_number = base_offset + (channel - 1) * 3 + 6

# Programming Lock 參數編號
lock_param = param_number + 1
```

**範例計算**:
- M1.CH1: base=0, param=0+(1-1)*3+6=6, lock=7
- M1.CH4: base=0, param=0+(4-1)*3+6=15, lock=16
- M2.CH1: base=12, param=12+(1-1)*3+6=18, lock=19

### 2.3 CIP Generic Message 結構

**Service Codes**:
- `0x0E` = Get Attribute Single (讀取)
- `0x10` = Set Attribute Single (寫入)

**Class Codes**:
- `0x04` = Assembly Object
- `0x0F` = Parameter Object

**標準訊息格式**:
```python
response = driver.generic_message(
    service=0x10,           # Set Attribute Single
    class_code=0x0F,        # Parameter Object
    instance=param_number,  # 參數編號
    attribute=1,            # Attribute 1 (Value)
    request_data=[value],   # 要寫入的值
    connected=False         # 使用 Unconnected Send
)
```

### 3.2 Step 1: 解鎖 Param1 (Global Nominal Current Lock)

**目的**: 解除全域標稱電流修改鎖定

**CIP 訊息**:
```python
response = driver.generic_message(
    service=0x10,        # Set Attribute Single
    class_code=0x0F,     # Parameter Object
    instance=1,          # Param1
    attribute=1,         # Value attribute
    request_data=[0],    # 0 = 解鎖
    connected=False
)
```

**預期結果**:
- Status: `Success`
- Param1 = 0 (解鎖狀態)

**可能錯誤**:
- `Path destination unknown` → 設備不支援此參數
- `Attribute not settable` → 參數唯讀
- `Permission denied` → 權限不足

**診斷方法**:
```python
if response and response.error:
    print(f"⚠️  Param1 解鎖失敗: {response.error}")
else:
    print("✅ Param1 已解鎖")
```

---

### 3.3 Step 2: 解鎖 Param2 (Global UI Lock)

**目的**: 解除全域 UI 操作鎖定

**CIP 訊息**:
```python
response = driver.generic_message(
    service=0x10,
    class_code=0x0F,
    instance=2,          # Param2
    attribute=1,
    request_data=[0],    # 0 = 解鎖
    connected=False
)
```

**預期結果**:
- Status: `Success`
- Param2 = 0 (解鎖狀態)

**說明**:
- Param2 控制 UI 面板的鎖定狀態
- 必須解鎖才能進行遠端參數修改
- 即使沒有連接 UI 面板也需要解鎖

---

### 3.4 Step 3: 解鎖通道 Programming Lock

**目的**: 解除特定通道的參數修改鎖定

**Parameter 計算**:
```python
lock_param = param_number + 1
```

**CIP 訊息**:
```python
response = driver.generic_message(
    service=0x10,
    class_code=0x0F,
    instance=lock_param,  # Param7, 10, 13, 16, 19, 22, 25, 28...
    attribute=1,
    request_data=[0],     # 0 = 解鎖
    connected=False
)
```

**範例**:
- M1.CH1: lock_param = 7
- M1.CH2: lock_param = 10
- M2.CH1: lock_param = 19

**重要性**:
- ⚠️ 這是最關鍵的解鎖步驟
- 若未解鎖，Step 4 寫入會失敗
- 必須針對每個通道單獨解鎖

**目的**: 設定目標通道的標稱電流

**CIP 訊息**:

```python
    instance=param_number,  # Param6, 9, 12, 15, 18, 21, 24, 27...

```

**資料格式**:

**預期結果**:

**成功條件**:
- Response.error = None
- Service = 0x10 (Set Attribute Single)
- Status = Success

### 3.6 Step 5: 等待裝置處理

**目的**: 給予設備足夠時間處理參數變更

**實作**:

**可調整範圍**:
- 最小建議: 1.0 秒
- 目前設定: 1.5 秒
- 最大建議: 3.0 秒（避免使用者體驗不佳）

## 階段 4: 設定驗證

### 4.1 驗證流程

**驗證方法**: 讀取 Input Assembly 0x65

```python
def _verify_nominal_current(self, driver, module, channel):
    # 讀取 Input Assembly
    response = driver.generic_message(
        service=0x0E,              # Get Attribute Single
        class_code=0x04,           # Assembly Object
        instance=0x65,             # Input Assembly
        attribute=3,               # Data attribute
        connected=False
    )
    
    if response and hasattr(response, 'value'):
        data = response.value
        offset = self.get_channel_offset(module, channel)
        
        # Byte 1 = Nominal Current
        nominal_current = data[offset + 1]
        return int(nominal_current)
    
    return None
```

---

### 4.2 Input Assembly 資料結構

**Module 1 通道資料**:
| Offset | Byte 0 | Byte 1 | Byte 2 | Byte 3 |
|--------|--------|--------|--------|--------|
| 0 (CH1) | Status | **Nominal** | Current MSB | Current LSB |
| 4 (CH2) | Status | **Nominal** | Current MSB | Current LSB |
| 8 (CH3) | Status | **Nominal** | Current MSB | Current LSB |
| 12 (CH4) | Status | **Nominal** | Current MSB | Current LSB |

**Module 2 通道資料**:
| Offset | Byte 0 | Byte 1 | Byte 2 | Byte 3 |
|--------|--------|--------|--------|--------|
| 16 (CH1) | Status | **Nominal** | Current MSB | Current LSB |
| 20 (CH2) | Status | **Nominal** | Current MSB | Current LSB |
| 24 (CH3) | Status | **Nominal** | Current MSB | Current LSB |
| 28 (CH4) | Status | **Nominal** | Current MSB | Current LSB |

**關鍵欄位**:
- **Byte 1 (Nominal Current)**: 標稱電流值 (1-20A)
- Byte 0 (Status): 通道狀態位元
- Byte 2-3: 實際電流值（100mA 單位）

---

### 4.3 驗證結果判斷

**成功案例**:
```python
if nominal_current == current_amps:
    print(f"✅ 驗證成功: M{module}.CH{channel} 標稱電流 = {nominal_current}A")

```

**失敗案例**:


```python
if nominal_current is None:

```

## Config Assembly 方法失敗分析

### 為何嘗試 Config Assembly？

**理論依據**:
- 手冊文件描述 Config Assembly (0x66) 為 "Read and write"
- Config Assembly 包含完整的 244 bytes 配置資料
- 理論上可一次修改多個參數

**預期流程**:
1. 讀取 Config Assembly (244 bytes)
2. 修改 Param1, Param2 (解鎖)
3. 修改目標通道的標稱電流參數
4. 修改通道 lock 參數
5. 寫回完整 244 bytes

---

### 失敗原因分析

#### 錯誤訊息: "Too much data"

**CIP 回應**:
```
Service: Set Attribute Single (0x10)
Class: 0x04 (Assembly Object)
Instance: 0x66 (Config Assembly)
Attribute: 3 (Data)
Request Data: 244 bytes
Response: Status = 0x13 (Too much data)
```

**真實原因**:
- ❌ **並非真的資料過大**
- ✅ **Config Assembly 在運行時是唯讀的**
- Config Assembly 只能在設備初始化時寫入
- 運行時修改必須使用 Parameter Object

---

### 測試過的其他方法

#### 方法 1: Set Attribute List (Service 0x03)
```python
response = driver.generic_message(
    service=0x03,           # Set Attribute List
    class_code=0x04,
    instance=0x66,
    request_data=attribute_list,
    connected=False
)
```
**結果**: ❌ 失敗 - "Service not supported"

---

#### 方法 2: 修改 Attribute 4
```python
response = driver.generic_message(
    service=0x10,
    class_code=0x04,
    instance=0x66,
    attribute=4,           # 嘗試其他 attribute
    request_data=[...],
    connected=False
)
```
**結果**: ❌ 失敗 - "Attribute not settable"

---

#### 方法 3: 部分資料寫入
```python
# 嘗試只寫入修改的部分
response = driver.generic_message(
    service=0x10,
    class_code=0x04,
    instance=0x66,
    attribute=3,
    request_data=modified_bytes[0:20],  # 只寫前 20 bytes
    connected=False
)
```
**結果**: ❌ 失敗 - "Too much data" 或 "Invalid parameter"

---

### 結論

**Config Assembly 限制**:
- ✅ 可讀取 (Get Attribute Single)
- ❌ 不可寫入 (運行時)
- ⚠️ 手冊文件與實際行為不符

**正確方法**:
- ✅ 使用 Parameter Object (Class 0x0F)
- ✅ 逐個參數修改
- ✅ 遵循解鎖順序

## 故障排除指南

### 問題 1: 命令無法執行

**症狀**:
```
❌ 未連接到設備，請先使用 'connect' 命令
```

**原因**:
- CIPDriver 未初始化
- 連線已中斷

**解決方法**:
1. 檢查連線狀態: 輸入 `status`
2. 重新連線: `connect <IP>`
3. 確認 Phase 3 系統檢查通過

---

### 問題 2: 通道編號錯誤

**症狀**:
```
❌ 通道編號必須在 1 到 8 之間
```

**原因**:

### 問題 10: 多通道同時設定衝突

```python
def set_multiple_channels(channels, values):
    # 一次性解鎖
    unlock_param1()
    unlock_param2()
    
    for ch, val in zip(channels, values):
        unlock_channel(ch)
        set_value(ch, val)
        time.sleep(0.5)
    
    # 驗證所有通道
    time.sleep(2.0)
    for ch, val in zip(channels, values):
        verify(ch, val)
```

```python
def test_read_all_params(driver, module):
    """讀取指定模組的所有相關參數"""
    
    print(f"\n=== Module {module} 參數讀取測試 ===\n")
    
    # Param1, Param2 (全域)
    for param in [1, 2]:
        response = driver.generic_message(
            service=0x0E,
            class_code=0x0F,
            instance=param,
            attribute=1,
            connected=False
        )
        if response and hasattr(response, 'value'):
            print(f"Param{param}: {response.value}")
        else:
            print(f"Param{param}: 讀取失敗")
    
    # 各通道參數
    base_offset = (module - 1) * 12
    for ch in range(1, 5):
        param_num = base_offset + (ch - 1) * 3 + 6
        lock_num = param_num + 1
        
        # 標稱電流
        response = driver.generic_message(
            service=0x0E,
            class_code=0x0F,
            instance=param_num,
            attribute=1,
            connected=False
        )
        nominal = response.value if (response and hasattr(response, 'value')) else 'N/A'
        
        # Lock 狀態
        response = driver.generic_message(
            service=0x0E,
            class_code=0x0F,
            instance=lock_num,
            attribute=1,
            connected=False
        )
        lock = response.value if (response and hasattr(response, 'value')) else 'N/A'
        
        print(f"CH{ch}: Param{param_num}={nominal}A, Lock{lock_num}={lock}")
```

```python
def analyze_config_assembly(driver):
    """詳細分析 Config Assembly 結構"""
    
    response = driver.generic_message(
        service=0x0E,
        class_code=0x04,
        instance=0x66,
        attribute=3,
        connected=False
    )
    
    if not response or not hasattr(response, 'value'):
        print("❌ 無法讀取 Config Assembly")
        return
    
    data = response.value
    print(f"\n=== Config Assembly 分析 (共 {len(data)} bytes) ===\n")
    
    # 全域參數
    print(f"Param1 (Global nominal lock): {data[1]}")
    print(f"Param2 (Global UI lock): {data[2]}")
    print()
    
    # Module 1
    print("Module 1:")
    for ch in range(1, 5):
        param_offset = (ch - 1) * 3 + 6
        lock_offset = param_offset + 1
        print(f"  CH{ch}: Param{param_offset}={data[param_offset]}A, Lock{lock_offset}={data[lock_offset]}")
    
    print()
    
    # Module 2
    print("Module 2:")
    for ch in range(1, 5):
        param_offset = 12 + (ch - 1) * 3 + 6
        lock_offset = param_offset + 1
        print(f"  CH{ch}: Param{param_offset}={data[param_offset]}A, Lock{lock_offset}={data[lock_offset]}")
    
    # Hex dump (前 64 bytes)
    print("\nHex Dump (前 64 bytes):")
    for i in range(0, min(64, len(data)), 16):
        hex_str = ' '.join(f'{b:02X}' for b in data[i:i+16])
        ascii_str = ''.join(chr(b) if 32 <= b < 127 else '.' for b in data[i:i+16])
        print(f"{i:04X}: {hex_str:<48} {ascii_str}")
```

```python
def test_all_channels(driver, num_modules):
    """測試所有通道的標稱電流設定"""
    
    print("\n" + "="*60)
    print("開始自動化測試")
    print("="*60 + "\n")
    
    test_values = [3, 5, 10, 15]  # 測試不同電流值
    results = []
    
    for module in range(1, num_modules + 1):
        for channel in range(1, 5):
            for test_amps in test_values:
                print(f"\n--- 測試 M{module}.CH{channel} = {test_amps}A ---")
                
                # 設定
                success = set_nominal_current(driver, module, channel, test_amps)
                
                # 驗證
                time.sleep(1.5)
                verified = _verify_nominal_current(driver, module, channel)
                
                # 記錄結果
                result = {
                    'module': module,
                    'channel': channel,
                    'target': test_amps,
                    'verified': verified,
                    'success': (verified == test_amps)
                }
                results.append(result)
                
                print(f"結果: {'✅ 通過' if result['success'] else '❌ 失敗'}")
                
                time.sleep(1.0)  # 通道間延遲
    
    # 統計報告
    print("\n" + "="*60)
    print("測試結果統計")
    print("="*60 + "\n")
    
    total = len(results)
    passed = sum(1 for r in results if r['success'])
    failed = total - passed
    
    print(f"總測試數: {total}")
    print(f"通過: {passed} ({passed/total*100:.1f}%)")
    print(f"失敗: {failed} ({failed/total*100:.1f}%)")
    
    if failed > 0:
        print("\n失敗案例:")
        for r in results:
            if not r['success']:
                print(f"  M{r['module']}.CH{r['channel']}: {r['target']}A → {r['verified']}A")
```

### C. CIP Service Code 對照

| Service Code | 名稱 | 說明 | 用途 |
|-------------|------|------|------|
| 0x01 | Get Attributes All | 讀取所有屬性 | 讀取物件完整資訊 |
| 0x0E | Get Attribute Single | 讀取單一屬性 | **讀取參數值** |
| 0x10 | Set Attribute Single | 設定單一屬性 | **寫入參數值** |
| 0x03 | Set Attribute List | 設定屬性列表 | 批次寫入（CAPAROC 不支援）|
| 0x4C | CIP Forward Open | 建立連線 | Connected messaging |
| 0x4E | CIP Forward Close | 關閉連線 | 結束 Connected messaging |

### D. CIP Class Code 對照

| Class Code | 名稱 | 說明 | CAPAROC 支援 |
|-----------|------|------|-------------|
| 0x01 | Identity Object | 設備識別資訊 | ❌ 不支援 |
| 0x04 | Assembly Object | 資料組合物件 | ✅ 支援 (0x64, 0x65, 0x66) |
| 0x0F | Parameter Object | 參數物件 | ✅ 支援 |
| 0xF5 | TCP/IP Interface | TCP/IP 介面 | ✅ 支援 |

### E. Assembly Instance 對照

| Instance | 名稱 | 方向 | 大小 | 說明 |
|---------|------|------|------|------|
| 0x64 | Output Assembly | Host → Device | 8 bytes | 控制命令 |
| 0x65 | Input Assembly | Device → Host | 32+ bytes | **狀態和標稱電流** |
| 0x66 | Config Assembly | Bidirectional | 244 bytes | 配置資料（運行時唯讀）|
