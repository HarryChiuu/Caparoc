fix(forward-open): 恢復 288-byte 請求並使用 EDS 原始 Path

根據專家分析，修正關鍵錯誤：

1. 恢復 288-byte Forward Open 請求 ✅
   - 44-byte 標頭 (不含 Config) 是錯誤的
   - 正確 = 44-byte 標頭 + 244-byte Config = 288 bytes
   - EDS config 2 定義: "244,Assem102" 表示必須附加 Config

2. Connection Path 使用 EDS 原始定義 ✅
   - EDS Path: "20 04 24 66 2C 64 2C 65"
   - 直接使用此字節序列，不做修改
   - 20 04 = Class 0x04 (Assembly Object)
   - 24 66 = Instance 0x66 (Config)
   - 2C 64 = Connection Point 0x64 (Output)
   - 2C 65 = Connection Point 0x65 (Input)

3. 移除錯誤的預先寫入 Config 步驟 ✅
   - Config 不需要預先寫入
   - Config 隨 Forward Open 一起傳送
   - 設備收到 Forward Open 時同時接收 Config

4. 增強除錯輸出 ✅
   - 顯示標頭 44 bytes
   - 顯示 Config 前 32 bytes
   - 詳細的錯誤分類與建議
   - 逐步流程顯示

5. 關鍵修正說明
   之前的錯誤理解：
   ❌ 44-byte 請求 (不含 Config)
   ❌ Connection Path 改為 "24 64 24 65" (修改 EDS)
   ❌ 預先寫入 Config Assembly
   
   正確做法：
   ✅ 288-byte 請求 (標頭 + Config)
   ✅ Connection Path 完全按照 EDS 定義
   ✅ Config 隨 Forward Open 一起傳送
